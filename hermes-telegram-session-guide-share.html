Telegram 多 Session 重溫指南

一個問題一個 session · 每個都有標題 · 一撳就返到去

2026年10月29日 · 香港 · 分享版本

1 · 你想做到嘅事

而家嘅情況

所有對話焗住喺同一條 DM 訊息流入面。雖然每個 session 都已經有自動標題，但畫面上冇分隔，向上 scroll 就會撞到其他話題嘅訊息，好難搵返舊嘢。

想做到嘅效果

每個查詢係一個獨立 session，喺 Telegram 側邊（topic 列）各自一格，topic 名 = session 標題，一撳就入返去，context 完全唔會撞。

/new · /title · /sessions		你（打命令）即刻，零設定session 層面隔離，但畫面仍然同一條流無唔需要

4 · 選項 A：即刻可用（零設定）

呢個唔需要改任何設定、唔需要 BotFather、唔需要 restart。你而家喺 Telegram 打得出嘅命令：

命令作用
/new 咖啡研究開新 session，並即時命名為「咖啡研究」
/new --yes 股票分析同上，但跳過確認對話框
/title 手沖筆記改當前 session 嘅標題（隨時改都得）
/sessions列出所有 session，當前嗰個標 (current)
/sessions search 咖啡按標題或 session ID 過濾（alias：/sessions find）
/sessions 咖啡研究直接返去該 session（等於 /resume）
/resume 咖啡研究完整寫法，效果一樣
/status睇當前 session 資訊（ID、model、token 用量）

實測驗證

我 run hermes sessions list --source telegram 見到你已經有舊 session 帶正常標題，例如「製作柏林博物館島資料列表、PDF 與地圖」、「9/30 柏林到布拉格火車班次及交通分析」。即係命名機制一直 work — 只係你冇用 /new 主動開新 session，所以舊對話混埋一齊。

建議習慣：每次開新話題前打一句 /new 主題名。之後任何時候 /sessions 就見到清清楚楚一個清單。

5 · 選項 B：/topic 多 Session 模式（主方案）

Telegram Bot API 9.4（2026 年 2 月）新增 Private Chat Topics — bot 可以直接喺 1 對 1 DM 開 forum 式 topic，唔需要開 supergroup。每個 topic = 一個完全獨立嘅 Hermes session：對話歷史、model 狀態、context window、session ID 全部獨立。

設定三步

1

開 BotFather Mini App
Telegram 搜尋 @BotFather，然後 tap 搜尋結果嗰一行開 Mini App。唔好用傳統 /mybots 文字選單 — 裡面冇 Threads Settings 呢個選項。

2

開 Threaded Mode
My bots → 你的 Bot → Bot Settings → Threads Settings → 開 Threaded Mode。同時保持「允許用戶建立 topic」開啟 （對應 allows_users_to_create_topics）。

3

返 DM 打 /topic
Hermes 會即時 call getMe 驗證兩個 flag。兩個都 true 就會開啟多 session 模式，並建立一個釘頂嘅 System topic 用嚟放狀態同命令。

開啟之後點用

  • 開新 session：DM 頂部 tap All Messages → 打任何一句 → Telegram 自動開一個新 topic，Hermes 喺裡面回覆。呢個 topic 就係一個獨立 session。
  • Topic 自動改名：第一次對話之後，Hermes 會生成 session 標題，並將 Telegram topic 名改成一樣（例如「New Topic」→「咖啡店比較」）。
  • 改名：覺得自動名唔靚，喺該 topic 內打 /title 好啲嘅名 覆蓋。
  • 重溫舊 session：直接 tap 返個 topic；或者喺 root DM 打 /sessions。
  • 舊 session 拉入 topic：喺 topic 內打 /topic <session-id>，前提係該 session 屬於你、而且未綁去其他 topic。
  • 睇當前綁定：喺 topic 內打 /topic（無參數）會顯示 session 標題同 ID。
  • 該 topic 重開新局：喺 topic 內打 /new，只影響呢個 topic。
  • 關閉整個模式：root DM 打 /topic off，root DM 回復正常，topic 唔會被刪。

開啟後嘅行為改變（要預先知道）

1. Root DM 變成 Lobby。開 topic 模式之後，直接喺 root DM 打普通訊息會被拒絕，Hermes 會提示你去 All Messages 或者開新 topic。系統命令（/status、/sessions、/usage、/help）喺 root 仍然 work。

2. Cron 報告嘅落點。你嘅 cron job delivery target 係 chat 你的 Telegram DM 而冇 thread_id，所以報告會繼續送去 root DM（即 All Messages / General）。我查過源碼，lobby 嘅攔截只針對你打入嚟嘅訊息，bot 主動推送唔受影響 — 但實際擺位建議開啟後即刻留意一次（例如等一份 697 或者定存報告）確認見到。

6 · 選項 C 同 D（需要我改 config）

選項 C：config 固定 topic 清單

喺 config.yaml 預先寫死幾個 topic，每個可以綁定一個 skill 自動載入。適合長期工作區，例如：

telegram:
  extra:
    dm_topics:
      - chat_id: 你的 Telegram DM
        topics:
          - name: 股票697
          - name: 咖啡搜尋
            skill: hong-kong-coffee-shops
          - name: 旅行研究
            skill: travel-research

好處：topic 名固定唔會被自動改、可以自動載入對應 skill（入「咖啡搜尋」topic 就自動識咖啡 workflow）。壞處：清單寫死，加 topic 要改 config + restart gateway（斷線 10–20 秒）。同 /topic 模式可以並存。

選項 D：dm_topic_auto_transfer

設 true 之後，root DM 打任何一句話會自動開一個新 topic + 新 session，完全唔需要記住打命令。

唔建議一開始就開：你隨手問一句「今日幾號」都會變成一個獨立 topic，好快就爆幾十個。建議先用熟 B 方案，覺得手動開 topic 麻煩先再考慮。

場景選項 A（純命令）選項 B（/topic）

8 · 建議路線

行 A + B 組合

第一步（今日）：用選項 A。每次開新話題打 /new 主題名，想搵返就 /sessions search 關鍵字。零風險、零設定，即刻見效。

第二步（有時間）：去 BotFather 開 Threaded Mode（三個撳，約一分鐘），返 DM 打 /topic。呢個就係你原本想要嘅效果 — 一個一個分開、每個有標題、一撳返到去。

第三步（可選）：如果發現某幾個主題（股票、咖啡、旅行）長期重複，話我知，我可以幫你寫選項 C 嘅 config，將佢哋變成常駐工作區連 skill 自動載入。改 config 之前我會先問你准，唔會自己動手。
